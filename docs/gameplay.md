# 遊玩規則

語言：[繁體中文](gameplay.md) · 總覽英譯見 [README.en.md](README.en.md)

單位沒有另行換算：畫面上的「萬立方公尺」「萬瓦」就是 controller 裡的整數。參數來自 [`Rock_Door_reservoir.java`](../src/reservoir_management_simulation/Rock_Door_reservoir.java)，亂數加在 controller。

## 一天怎麼結

順序固定，寫在 `one_day()`：

1. 加上「今日預計進水」（昨天抽好的天氣）。
2. **供水**：勾選且水位 ≥ `max/15` → 扣 `used_water()`，停水天數歸零；否則停水 +1。
3. **發電**：勾選且水位 ≥ `max/10` → 扣 `make_power()`，停電天數歸零，昨日發電量顯示 `80+rnd(40)` 萬瓦；否則停電 +1、發電量 0。
4. **閘門**：全開扣 1500、半開扣 750，監視器換圖。洩洪時沒發警報 → 民怨 +1；沒洩洪卻發警報 → 也 +1。
5. 檢查失敗。沒失敗才抽明天天氣、算進水、換背景、天數 +1、累加人工雨冷卻。

「度過一月」只是在 `game_over == false` 時把上面跑 30 次。

## 天氣與進水

| 天氣 | `water_in` 下限 | 再加亂數 | 實際區間 |
| --- | ---: | ---: | --- |
| 晴 | 70 | 0–69 | 70–139 |
| 陰 | 200 | 0–99 | 200–299 |
| 雨 | 600 | 0–899 | 600–1499 |

新局與每天結束各抽一次 `rnd(3)`。按「人工雨」且冷卻滿 30 天：當天日誌寫「製造人工雨」，**下一次**抽天氣時強制下雨，冷卻歸零。冷卻未滿會寫還要幾天。

## 庫容與水位

| 量 | 公式 |
| --- | --- |
| 最高蓄水量 | `20000 + rnd(2000)` → 20000–21999 |
| 開局水位 | `1000 + rnd(20000 - 2000)` → 1000–18999（用的是基準 20000，不是滾出來的 max） |
| 滿水 | `now > max * 2/3` |
| 中水位 | `now > max / 3` |
| 缺水 | 其餘 |
| 乾涸危機 | `now < max / 15` |
| 潰堤危機 | `now > max / 15 * 14` |

水位低於 0 會夾回 0。**超過 max 是潰堤**，不是夾回 max。

## 操作代價

| 動作 | 條件 | 效果 |
| --- | --- | --- |
| 供水 | `now ≥ max/15` | 扣 `150 + rnd(100)` |
| 發電 | `now ≥ max/10` | 扣 `150 + rnd(100)` |
| 閘門全開 | 無水位門檻 | 扣 1500 |
| 閘門半開 | 無水位門檻 | 扣 750 |
| 蒸發 | — | 類別有 `evaporation() = 10`，**沒接上** |

閘門可以在水位不夠時仍開。這是洩洪，不是供水。

## 失敗（你被調職了）

可同時成立，日誌會列所有原因。

| 條件 | 門檻 |
| --- | ---: |
| 連續停水 | 3 天 |
| 連續停電 | 7 天 |
| 潰堤 | `now > max` |
| 民怨 | 3 次 |

民怨來源只有兩種：洩洪未警報、亂發警報。關著閘門且不點警報，不會加民怨。

失敗後「度過一天」變成「再試一次」，呼叫 `again()` 重抽庫容與天氣。

## 參數從哪來

2023 報告寫進出水與氣候頻率「皆為參考石門水庫的數據做成的變數範圍」，連結是公開頁，不是本倉資料集：

- [水庫即時水情](https://water.taiwanstat.com/)
- [石門水庫監測整理](https://monitor.wfuapp.com/2020/05/shimen-reservoir.html)
- 水利署水庫蓄水統計（報告裡的 `fhy.wra.gov.tw` 舊網址）
- [經濟部水利署北區水資源分署](https://www.wranb.gov.tw/)

本遊戲**不是**石門水庫的數值模型。沒有蒸發、沒有下游渠道、沒有真實日雨量序列。
